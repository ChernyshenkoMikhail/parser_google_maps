# parser_google_maps

Асинхронный парсер на базе **Python** и **Playwright** для автоматизированного сбора, структурирования и выгрузки данных о заведениях общественного питания (рестораны, бары, кофейни, пекарни и др.) в центре Мадрида из карточек **Google Maps** с последующей синхронизацией с локальным CSV-файлом и **Google Таблицами**.

---

## 📋 Основные возможности и архитектура

### 1. Гео-сеточный поиск по категориям (Discovery Phase)
Чтобы обойти ограничение Google Maps на количество отображаемых результатов в одной поисковой выдаче, скрипт использует поиск по координатной сетке:
* **Сетка координат (`GRID_COORDS`):** 25 опорных точек (матрица $5 \times 5$ с шагом `0.0050°` по широте и `0.0060°` по долготе), покрывающая центральные районы Мадрида (Sol, Malasaña, Chueca, La Latina, Salamanca, Retiro и др.) на зуме `17z`.
* **Категории поиска (`CATEGORIES`):** 10 целевых запросов на испанском языке (`Restaurante`, `Bar de tapas`, `Cafetería`, `Taberna`, `Bar`, `Pizzería`, `Hamburguesería`, `Sushi`, `Comida rápida`, `Pastelería`).
* **Умная прокрутка фида (`get_urls_for_task`):** эмуляция скроллинга контейнера выдачи (`div[role="feed"]`) до 25 итераций с автоматической остановкой при достижении конца списка (3 цикла без прироста новых ссылок).
* **Очистка и дедупликация ссылок:** отсечение query-параметров URL и мгновенное сохранение уникальных ссылок в кэш-файл `collected_urls.txt` после каждой точки поиска.

### 2. Детальный парсинг карточек заведений (`parse_restaurant_ru`)
Для каждого уникального URL скрипт открывает карточку с принудительной русской локалью (`?hl=ru`) и извлекает следующие поля:
* **Название заведения** (из основного заголовка `h1.DUwDvf`).
* **Тип заведения / категория** (например, *Ресторан*, *Тапас-бар*, *Кофейня*).
* **Средний чек** — многоуровневое извлечение из шапки карточки, `aria-label` и основного блока текста с поддержкой числовых диапазонов (`10–20`, `20–30`, `50+`) и резервным сбором ценовых символов (`€`, `€€`, `€€€`, `€€€€`).
* **Точный адрес** (из кнопки адреса с очисткой системных префиксов `Адрес:`, `Dirección:`, `Address:`).
* **Средняя оценка и общее количество отзывов**.
* **Детальное распределение оценок по звездам (`5★`, `4★`, `3★`, `2★`, `1★`)** — скрипт принудительно переключается на вкладку «Отзывы», дожидается рендеринга DOM-таблицы гистограммы (`tr.BHOKXe`) и парсит точное количество оценок каждого уровня через JS-инъекцию.

### 3. Отказоустойчивость, кэширование и пакетная выгрузка
* **Асинхронная очередь (`asyncio.Semaphore`):** параллельная обработка в `CONCURRENCY = 4` потока с единым контекстом браузера Chromium и автоматическим принятием cookie-баннеров (`accept_cookies`).
* **Resume-режим (докачка):** при перезапуске скрипт сверяет список ссылок из `collected_urls.txt` с уже обработанными записями в `madrid_centro_restaurants.csv` и парсит только недостающие карточки.
* **Флаг сброса (`RESET_CSV_WITH_ZEROS`):** позволяет при необходимости удалить старый CSV-файл и перезапустить сбор данных с нуля по уже собранной базе URL без повторного сканирования карты.
* **Пакетное сохранение и экспорт (Batching):** каждые **20 обработанных карточек** данные сохраняются локально в `madrid_centro_restaurants.csv` (кодировка `utf-8-sig` для корректного открытия в Excel) и отправляются POST-запросом в формате JSON на веб-хук **Google Apps Script** (`WEB_APP_URL`) для обновления Google Таблицы в реальном времени.

## 📊 Структура выходных данных

| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `Название` | `str` | Официальное название заведения в Google Maps |
| `Тип заведения` | `str` | Основная категория заведения |
| `Средний чек` | `str` | Диапазон цен (например, `10–20`), символы `€–€€€€` или `Нет данных` |
| `Адрес` | `str` | Полный почтовый адрес заведения |
| `Средняя оценка` | `str` | Рейтинг от `1,0` до `5,0` (с запятой в качестве разделителя) |
| `Всего отзывов` | `int` | Общее количество оценок |
| `5 звезд` ... `1 звезда` | `int` | Точное количество отзывов для каждой оценки от 5 до 1 |
| `Ссылка` | `str` | Прямой очищенный URL карточки в Google Maps |

## ⚙️ Конфигурация

Основные параметры настраиваются в начале скрипта:
* `WEB_APP_URL` — URL развернутого веб-приложения Google Apps Script (заканчивается на `/exec`).
* `CONCURRENCY` — количество одновременно открываемых вкладок браузера (по умолчанию `4` для стабильной работы в Google Colab).
* `RESET_CSV_WITH_ZEROS` — `True` для принудительного пересбора карточек по кэшу ссылок; `False` для продолжения с места остановки.
* `GRID_COORDS` / `CATEGORIES` — настройка географической зоны и списка поисковых запросов.

## 🛠️ Стек технологий
* **Python 3** (ориентировано на запуск в среде Google Colab / Jupyter Notebook)
* **Playwright (Async API)** — управление headless-браузером Chromium и исполнение JS в контексте страницы
* **Pandas** — формирование датафреймов и экспорт в CSV
* **Requests** — отправка данных по HTTP в Google Apps Script
